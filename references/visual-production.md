# Cohesive visual production and pitch packages

## One visual bible

Define camera/projection, sprite or model scale, palette roles, silhouettes, material style, lighting, animation cadence, outlines, typography, HUD zones, effects priority, and accessibility cues. Every asset and interface derives from this bible, including upgrade icons and the home base.

A gameplay choice changes the build, not the entire art direction. Do not combine three visual styles as though they were three reward cards. Alternative themes are separate concept packages, each internally consistent.

## Produce, then admit

Asset generation or procurement is separate from asset admission. Before adding an asset to the game, check origin, license/permission record, dimensions, transparency, import settings, animation consistency, memory footprint, and fit with the bible. Record manual cleanup and source files. A provider's existence does not establish rights to a particular asset.

Use available image, audio, 3D, asset-vendoring, and rendering tools only within their actual capabilities. Do not assume access to a paid image/video model, game engine, or storefront SDK. Obtain spending authorization before paid jobs. Never promise generated production-ready animation without inspection.

## Concept-stage flyer or box treatment

When `pitch` is requested before gameplay exists, deliver a labeled concept package: hero image; one gameplay-style mockup; a three-choice upgrade screen; a home-base screen; selling points tied to the proposed rules; several paragraphs of operational description; and a technical gameplay manual.

The manual covers controls, run pacing, encounters, temporary upgrades, example synergies, resources, death/extraction/banking, facility tiers, recruits, routes, save behavior, and known prototype assumptions. Prefer real text layout for labels and numerical UI over unreliable tiny generated lettering.

Label all non-captured visuals 'Concept mockup, not captured gameplay.' Do not add platform logos, storefront availability claims, review quotes, ratings, or release dates that are not established. Concept names are working titles until checked.

## After the slice

Replace mockups with actual captured gameplay where possible. Record the build, scene, viewport, seed, and whether any compositing occurred. Validate that marketing screenshots show features in that build. The final art gate is cohesive, readable gameplay, not a striking poster in isolation.
